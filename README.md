CS 360 Mobile App Development Portfolio
CloudForge Inventory Management — Project Three
CloudForge Inventory Management is the Android inventory-tracking application I developed for CS 360. This course project builds on my larger CloudForge software concept, but the submitted mobile application focuses specifically on inventory management.
1. App requirements, goals, and user needs
The goal was to give technicians, small shops, and operations teams a straightforward way to track inventory without relying on paper records or disconnected spreadsheets. Users needed to create an account, sign in, and add, view, edit, and delete inventory items. Each item records a name, quantity, location, and low-stock threshold. The application also needed to preserve inventory data between sessions and support optional low-stock alerts. These requirements addressed the need for reliable, accessible stock information during daily work.
2. User-centered screens and interface design
The app includes registration and login screens, an inventory display, controls for adding and editing items, and alert settings. I designed the inventory view to make item details and quantities easy to locate and update without navigating through unnecessary screens. Clear actions for adding, editing, and deleting records support common user tasks, while low-stock warnings bring attention to items that need action. Starting with the UI design from Project Two helped me keep the layout consistent as I implemented the functionality in Project Three. I consider the design effective because it supports the tasks users need to complete rather than adding complexity for its own sake.
3. Coding process and strategies
I developed the application in Android Studio using Java and SQLite for local data storage. I approached the work by building on the existing UI foundation and connecting individual screens to the required functions. I focused on account validation, inventory database operations, input handling, and optional SMS alert behavior. Breaking the work into smaller features and testing each workflow helped me isolate problems and avoid changing too many components at once. I plan to use this same incremental approach, along with clear separation of interface and data responsibilities, in my future software projects.
4. Testing and what it revealed
I tested the app through its main user workflows, including account creation, successful login, rejection of an incorrect password, and adding, editing, and deleting inventory records. To verify persistence, I changed an item's quantity from 55 to 45, closed the application, reopened it, and confirmed that the updated quantity remained stored. I also checked low-stock behavior with SMS alerts enabled and disabled. With alerts enabled, the app reported that a low-stock SMS had been requested; actual message delivery was not verified. Testing mattered because it showed whether the database, user interface, and alert logic behaved together as intended rather than merely appearing correct on screen.
5. Innovation and overcoming challenges
One of the biggest challenges was getting the completed Project Three functionality integrated into a stable Android Studio project. Earlier project packages did not work as expected, so I returned to the working Project Two foundation and incorporated the required functionality from there. This taught me to preserve a known-good starting point, make controlled changes, and verify important features after each major change. That approach is more efficient than repeatedly rebuilding an unstable project.
6. My most successful component
The SQLite-backed inventory management workflow best demonstrates my progress. I connected the user interface to persistent records and verified that items could be created, updated, deleted, and retrieved after restarting the app. Seeing the quantity update persist across sessions was especially meaningful because it confirmed that the application was doing more than displaying temporary screen data. This component demonstrates my ability to combine interface design, database operations, and practical testing into a working mobile feature.
Portfolio artifact
The Project Three Android Studio application ZIP is included in this repository. It contains the finished code and UI developed for this course. The classroom application is not presented as a published Google Play Store release; production publication would require additional release testing and review of the SMS permission and alert approach.
